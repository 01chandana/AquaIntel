# AquaIntel — Water Infrastructure Monitoring Platform

A full-stack IoT monitoring and alerting web application built from scratch with
FastAPI, SQLite and vanilla JavaScript. Tracks physical assets (pumps, stations),
ingests sensor telemetry, raises threshold alerts, detects statistical anomalies,
and forecasts future threshold breaches for predictive maintenance.

---

## Features

**Asset management**
- Create, list, and edit assets (name, status)
- Search and filter by name or status
- CSV export of the asset register
- Per-asset detail page with full sensor history

**Telemetry**
- Sensor reading ingestion endpoint (asset, reading type, value, timestamp)
- Live line chart of recent readings
- Built-in simulator that generates readings every 3 seconds for demos

**Alerting**
- User-defined alert rules (per asset, per reading type, max threshold)
- Alerts raised automatically when an incoming reading breaches a rule
- Real browser push notifications when new alerts fire
- Alert history view

**Analytics**
- **Anomaly detection** — flags readings more than 2 standard deviations from
  the mean (z-score method); anomalous points are highlighted on the chart
- **Predictive maintenance** — fits a linear regression over a sensor's history
  and estimates how many hours until the value is projected to cross a given
  threshold

**Authentication & authorization**
- Signup and login with bcrypt-hashed passwords
- JWT access tokens
- Role-based access control: **admin** (full write access) vs **viewer**
  (read-only); write endpoints are enforced server-side, and admin-only UI
  controls are hidden for viewers

**Interface**
- Multi-page dark-themed dashboard (Dashboard / Assets / Alerts / Asset Detail)
- Live-updating summary cards, charts, and recent activity feed
- Mobile responsive — usable on a phone browser

## Running the project

**Requirements:** Python 3.11+

**1. Install dependencies**

```bash
pip install fastapi uvicorn sqlalchemy python-jose bcrypt
```

**2. Start the server**

```bash
python -m uvicorn main:app --reload
```

To also reach the app from another device on the same network (e.g. a phone):

```bash
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

**3. Open the app**

- App: http://127.0.0.1:8000/login-page
- Interactive API docs: http://127.0.0.1:8000/docs

**4. Create an account**

On the login page choose *Sign up*, pick the **Admin** role for full access, then
log in with those credentials.

## How the analytics work

**Anomaly detection.** For a given asset, the mean and sample standard deviation
of all its readings are computed. Any reading whose distance from the mean
exceeds 2σ is reported as an anomaly, along with its deviation in units of σ.
At least 3 readings are required before any result is returned.

**Breach prediction.** Readings are converted to (seconds-elapsed, value) pairs
and a least-squares linear regression is fitted. If the resulting slope is
positive, the line is solved for the point where it crosses the configured
threshold, and the remaining time is reported in hours. If the slope is zero or
negative, the endpoint reports a stable or decreasing trend and makes no
prediction. At least 4 readings are required.

Both are deliberately simple, explainable statistical methods rather than trained
models — appropriate for the data volumes involved and easy to reason about.

## Known limitations

- SQLite with no migration tooling — schema changes require recreating the
  database file, so existing data is lost when models change
- `reading_type` matching is case-sensitive (`pressure` ≠ `Pressure`)
- Alert rules support a single comparison type (value above a maximum)
- The JWT secret key is hardcoded and would need to move to an environment
  variable before any real deployment
- CORS is fully open (`allow_origins=["*"]`), suitable for local development only
- Browser notifications require the tab to be open

## About this project

Built solo as a first full-stack project, to learn backend development end to
end: REST API design, ORM modelling, password hashing, token-based auth,
role-based authorization, and a JavaScript frontend consuming the API. The
domain and feature set are inspired by enterprise water-infrastructure
monitoring platforms; this implementation covers the core concepts (asset
registry, telemetry, rule-based alerting, anomaly detection, predictive
maintenance) as a single working application rather than a distributed system.
